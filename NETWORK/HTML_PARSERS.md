# ESJ Zone HTML 解析器设计

## 1. 解析原则

- 以语义选择器和链接 URL 为主，不依赖第几个 div。
- 保留原始 href，另存规范化 URL；不要丢弃章节链接中的 # 片段。
- 处理传统服务端 HTML、空表、Loading 占位和本地 tab。
- 只把 DOM 中可观察字段标记为已知，缺失字段使用 null 或 UNKNOWN。
- 小说正文使用 HTML 级别保存，不能只取纯文本，否则会丢失段落、换行和插图。

## 2. 通用页面骨架

常见公共选择器：

| 目标 | 选择器 | 备注 |
|---|---|---|
| 页面标题 | document.title | 中文页面，lang 属性观察为 en |
| 主标题 | h1, h2, h3 | 不同模板层级略有差异 |
| 主导航 | header a[href] 或公共导航区域 | 以 href 为准 |
| 创建小说模态 | form#createBook | 多数页面都会带，不能当作当前页面主表单 |
| 会员侧栏 | /my/ 开头的链接 | 登录态页面出现 |
| 分页 | #page-selection a、.pagination a | 服务端分页与本地分页并存 |

## 3. 小说列表卡片

适用页面：/、/update/、/list-*、/tags*。

主选择器：

~~~css
.card.mb-30
.card.mb-30 h5.card-title a
.card.mb-30 .card-ep a
.card.mb-30 .card-author a
.card.mb-30 .card-img-tiles
.card.mb-30 .lazyload
.card.mb-30 .card-other
~~~

字段映射：

| 字段 | 选择器/来源 | 归一化 |
|---|---|---|
| 小说标题 | .card.mb-30 的 title 属性，或 h5.card-title a 文本 | 保留原文 |
| 详情 URL | h5.card-title a[href] 或 .card-img-tiles[href] | 匹配 /detail/{novelId}.html |
| 小说 ID | 详情 URL | 十进制字符串，模型中可保留 string |
| 最新章节标题 | .card-ep a 文本 | 纯文本 trim |
| 最新章节 URL | .card-ep a[href] | 允许 .cc 与 .one 主机 |
| 作者 | .card-author a 文本 | 保留原文 |
| 作者/标签 URL | .card-author a[href] | 通常 /tags/{author}/ |
| 封面 | .lazyload[data-src] | 优先 data-src，不依赖最终 img |
| 字数 | .icon-file-text 所在 .card-other | 去逗号，失败为 null |
| 观看数 | .icon-eye 所在 .card-other | 同上 |
| 收藏数 | .icon-heart 所在 .card-other | 同上 |
| 章节/文章数 | .icon-feather 所在 .card-other | 同上 |
| 讨论数 | .icon-message-square 所在 .card-other | 同上 |
| R18 标记 | .product-badge.top | 只记录是否存在和文案 |

列表页每页观察到 40 张卡片。数字字段的图标与数字位于相邻文本中，建议使用字段节点的 innerText 后正则提取，而不是依赖空格数量。

### 3.1 首页上周热门

首页桌面侧栏的上周热门榜直接嵌在首页 HTML 中，并非独立接口。客户端只取前十名用于首页横向轮播。

| 字段 | 选择器/来源 | 备注 |
|---|---|---|
| 榜单项 | `.widget-categories-hot li` | DOM 顺序即排名 |
| 小说标题 | `li > a` | 纯文本 trim |
| 详情 URL | `li > a[href*='/detail/']` | 相对详情链接 |
| 上周热度 | `li > span` | 不是详情页累计观看数 |

榜单本身不提供封面、简介、作者、类型或 R18 标记。客户端先按规范化小说链接复用首页快照中的详情元数据并发布首页内容；轮播可见且页面恢复交互后，只串行补全当前及相邻一项，离开首页或滚出可见区域时取消补全。详情继续复用六小时 HTML 缓存，不因首页下拉刷新强制刷新详情页。补全期间暂停自动轮播，避免慢请求被每次自动翻页取消；用户仍可手动翻页。页面总请求上限维持六，热门详情与过期 HTML 后台刷新同属低优先级，最多占用一个请求槽，排队中的前台请求优先。启动、登录及切换镜像不再自动请求留言板和灌水楼，进入对应页面时沿用原有缓存与加载流程。

轮播可见性由首页组合阶段读取列表的可见项状态并计算为普通布尔值，再传给轮播条目。不得在 `LazyColumn` 项目列表构建过程中读取同一列表的 `layoutInfo` 或基于它的派生状态，否则项目提供器会反向依赖自身的测量结果，在恢复已有首页快照时可能触发持续状态重算并卡住主线程。

首页主请求失败时保留已显示内容并提供重试。一周更新独立记录失败并保留上次列表，局部重试只请求一周更新，不重刷首页和热门详情。

当前可见 Tab 的封面优先请求网络，隐藏 Tab 的图片组件仍可读取本地文件、内存及磁盘缓存。首页按 LazyColumn 可见项位置，只预取接下来最多六张不同封面；滚动改变预取窗口时取消旧任务，等待短暂稳定后继续，遵守成人内容和隐藏推荐设置。图片客户端总并发及同主机并发维持八，后台首页预取最多两并发，只写磁盘缓存并跳过解码。仅成功请求记入本轮完成集合，刷新会重新建立集合。首次安装仅在首页可见时预取；后续启动允许隐藏首页预热最前面的六张封面。预取与显示继续复用 Coil 镜像缓存键。

书架后台持久化最多两并发：先转换已有本地封面，网络补充等待首页数据和当前预取结束，但可见书架图片无需等待后台任务。持久文件使用带版本的 `thumb_v1_*.img` 名称；静态图片按比例缩到最长边 720 像素，比较 WebP、无透明通道时的 JPEG 与原文件，选择最小结果后原子提交，动态图保留原文件。旧封面在转换成功前继续可读，封面查看与导出仍使用各自原图来源。书架维护时查询所有账户的可见条目，在数据库事务内按引用清理废弃封面；只在新缩略图已存在时回收对应旧副本。

从书架（列表、网格和最近阅读展示）或首页（普通卡片及热门轮播）进入详情页时，直接传递点击位置已成功解码的图片，详情首帧沿用该图片，无需重新读取文件或图片缓存才能显示。热门轮播继续使用自身的共享元素标识，仅复用图片交接；重复出现的同一作品按实际点击位置交接。来源尚未加载出图片或没有来源卡片时，继续使用持久本地文件或 Coil 内存／磁盘缓存路径。详情返回的新封面地址只在图片解码成功后替换当前图片，加载期间及失败时保留最后一次成功图片；详情退出并完成返回转场后释放交接图片引用。详情未提供有效封面地址时继续使用入场封面；原图查看仍使用详情原图地址。图片请求沿用共享加载器、镜像缓存键及既有缓存策略，不额外强制检查远程图片更新。

首次启动通过应用 no-backup 目录中的 `cover_loading_started` 标记识别，模式在同一进程中保持稳定；没有标记但已有 `general` 数据库的旧安装按后续启动处理。图片下载并发维持八，热门详情按可见轮播项串行补全。

封面数据与显示状态分开记录：`Unknown` 表示旧记录等来源尚未确认，`Resolving` 表示正在查询本地文件或补全详情，`Missing` 仅表示已完成的页面解析没有有效封面，`Loading` / `Loaded` 对应实际图片请求，`Failed` 区分超时、其他网络错误、本地或缓存不可用及其他错误。热门榜保留详情补全结果与失败类别，书架和本地历史保留进程内补全状态；书签找不到本地副本、下载清单没有封面地址不能证明站点无封面。隐藏 Tab 缓存未命中归为不可用，不冒充网络异常。封面组件对无图、加载中和请求失败采用低对比度占位；有效图片请求失败时提供仅重试该封面的按钮，已成功加载的图片在替换失败时保留。普通图片、头像和正文图片仍沿用各自既有失败处理。

## 4. 搜索与标签结果

客户端将关键词作为单一路径段编码后再构造首屏与分页 URL；因此 `#`、`?`、`/` 和空格不会改变路由层级。分页仍使用 `/tags-{sort}/{keyword}/{page}.html`。

页面选择器：

| 目标 | 选择器 |
|---|---|
| 结果标题 | h1, h2, h3 中包含 搜尋結果： |
| 类型 | select#category |
| 排序 | select#sorting |
| 结果卡片 | .card.mb-30 |
| 分页 | #page-selection a |

下拉值：

- category：0=全部、2=原創、1=日輕、3=韓輕
- sorting：1=最新更新、2=最新上架、3=最高評分、4=最多觀看、5=最多文章、6=最多討論、7=最多收藏、8=最多字數

首页随机推荐复用全部类型的列表路由：`/list-04`（最多观看）、`/list-01`（最新更新）、`/list-02`（最新上架），每批分别抽取 6、12、6 本，最后混合打乱。客户端抽取范围分别限制在前 5、20、5 页，不再随机访问全站历史分页；这是客户端推荐策略，不是网站提供的推荐接口或时间范围保证。

首次读取每类列表时直接利用返回的第一页卡片，后续需要补充时在限定范围内随机选择未访问页。页内随机排序，未展示卡片保留给下一批；三类来源和连续批次共用小说链接（缺失时使用书名）去重，并遵守成人内容开关。每批每类最多读取 3 页（包括首次读取），不足配额时减少当批数量，不挪用其他来源名额。限定候选全部耗尽后停止追加，点击“换一批”可开启新一轮；收起保留候选和去重记录，首页刷新或成人内容设置变更时清空。

搜索输入框不是初始可见控件。先点击可见 div.search，再填写 input[name="site_search"]，按 Enter 后进入 /tags/{keyword}/。

## 5. 小说详情页

URL：/detail/{novelId}.html

### 5.1 基础字段

| 字段 | 选择器/来源 |
|---|---|
| 详情容器 | .book-detail |
| 标题 | .book-detail h2 |
| 作者 | .book-detail a[href^="/tags/"] |
| 访问数 | #vtimes |
| 收藏数 | #favorite |
| 字数 | #txt |
| 封面 | .product-gallery img，实际图片常在 src 或懒加载属性 |
| Web 生肉 | .book-detail a[rel*="nofollow"] 或外部 URL |
| 收藏按钮 | button.btn-favorite |
| 书籍论坛 | a.btn-forum |
| 章节 tab | #integration |
| 章节排序按钮 | #integration button 中的 正序/倒序 文案 |
| 内容标签 | .widget-tags a, .widget-tags a.tag, a.tag[href*="/tags/"] |

详情页以 `.book-detail h2` 的实际标题为书名；仅在标题缺失时沿用有效的列表入口书名。名称等于当前作品 ID 或详情地址时视为身份占位，不进入详情缓存；不按“纯数字”一概过滤，`1984` 等真实数字书名仍可使用。

导航恢复不再把作品 ID 当作书名。阅读器先从本地历史、书架、书签、统计和离线资料补全，缺失时再获取详情标题；成功后仅修复各处错误的名称，不改阅读进度、累计时长或收藏同步意图。启动、备份恢复和进入历史／书签／统计／下载页后也会检查旧记录；离线且本地没有真实书名时保留未知状态，下次启动或进入这些页面时重试补全。

详情样本的 button.btn-favorite 文案为 已收藏，类名含 btn-danger；这是当前用户状态，不是通用默认值。
内容标签容器为 .widget.widget-tags（页面分别在移动端 .widget-tags.hidden-lg-up 与桌面侧栏呈现相同标签），每个标签链接为 a.tag[href^="/tags/"]；解析器去重后得到完整标签列表。包含 R18 标签时作为小说成人内容标识。

简介排版依据 2026-10-15 的两份本地 MHT 详情存档（作品 ID `1745928457`、`1781722025`）：实际容器均为 `.description`，前者含 `strong > span[style="font-size:30px;"]`，后者含居中的 `p`、`strong > em > span[style="font-size:24px;"]`，两者都有 `<p><br></p>` 空段落。存档 CSS 使用 `line-height: 1.5`、段落下边距 `16px`，简介设置 `overflow-wrap: break-word; word-break: break-all`；离线浏览器中大字号的实际行高分别为 `45px`、`36px`。

客户端简介单独保存每个组件对应的段落对齐及段尾间距，不改变章节正文的共享组件解析。展开简介使用默认 `16sp` 字号；每个显式换行分段按其中最大字号的 1.5 倍设置行高，并为注音内联占位保留高度。保留字号、粗体、斜体、显式换行和空段落，`p` 段尾留 `16dp`；末尾单个 `<br>` 不额外增加第二个空行。文字占满应用实际可用宽度并自动换行，图片沿用容器宽度约束，不引入网页固定宽度或固定文本高度。收起时继续使用紧凑纯文本预览。浏览器存档渲染不代表 Compose 或 Android 系统字体缩放已完成实机验收。

### 5.2 章节目录

兼容选择器：

~~~css
#integration #chapterList a[data-title]
#integration #chapterList a[data-title] p
#integration details
#integration details > summary
#integration details a[data-title]
#integration details a[data-title] p
~~~

字段：

- `#chapterList` 可以混合组外章节、说明段落与 `details`，不能用后代链接选择器将整个容器平铺。
- 从 `#integration` 按 DOM 顺序递归遍历包装节点，遇到 `details` 保留分组，标题取直接子节点 `summary`，支持嵌套分组与空分组；章节链接只解析一次。
- 折叠初始状态来自 `details[open]`；客户端保存当前页面的展开状态。折叠只影响显示，完整章节顺序仍用于阅读导航、历史和下载。
- 2026-09-01 浏览器验证 `1635692176`：`#chapterList` 内五组分别有 18、99、102、100、62 个链接，均默认收起，组外另有三个章节链接。
- 章节标题：a[data-title] 的 data-title，若缺失再取其中 p 文本。
- 章节 URL：a[href]。
- 小说 ID/帖子 ID：从 /forum/{novelId}/{postId}.html 解析。
- 外部顺序：DOM 顺序；正序/倒序按钮可能改变显示顺序。

已验证的当前扁平模板包括 1772649515（129 个章节）与 1784452084（52 个章节）；旧样本还包含 10 个 details，前 9 卷有内容，最后一卷 Q&A 为空。目录链接可能包含非数字标题，客户端不能用“数字章节连续”替代实际 DOM 目录。

## 6. 章节/帖子页

URL：/forum/{novelId}/{postId}.html

### 6.1 正文

~~~css
.forum-content.mt-3
.forum-content.mt-3 p
.forum-content.mt-3 img
~~~

保存策略：

1. 保留正文容器的 innerHTML。
2. 允许 p、br、img 以及 section/div/article/blockquote 等嵌套容器排版节点；解析时递归提取独立段落块以避免换行坍缩。
3. 图片 URL 用 img[src] 提取，并保留 alt/class。
4. 评论区不并入正文，只取 .forum-content.mt-3。

离线任务读取章节及提交章节密码时，URL 均以任务入队时保存的站点基址解析；前台切换镜像不改变该任务的请求主机。

阅读器识别密码页后，将其作为未解锁章节保留在双向阅读窗口内；滚动与分页模式均在章内显示密码输入、验证状态及评论入口，不弹出密码对话框。相邻章节按完整目录继续加载，未解锁章节的阅读进度保持为零。密码错误或请求失败仅更新本章的验证状态；成功后在原位置替换正文并按既有流程离线保存，不清空前后章节。密码输入仅在组件内存中保留，不进入阅读状态或导航参数。

从本地历史续读未解锁章节时，密码页不消费已保存的进度和锚点，也不覆盖历史位置；正文解锁并完成排版后才应用原恢复目标。用户主动滚动或滑动到其他章节时取消延迟恢复，恢复后续阅读进度保存及分页点击、音量键翻页；停留在原密码章节或仅发生加载、排版变化时继续保留恢复目标。已有离线正文时仍直接恢复。

评论沿用独立的 `getChapterComments` / `PageKind.COMMUNITY` 获取与解析，不以正文解锁成功为前提；章内评论按钮使用该章节自己的 URL，工具栏及侧滑评论仍跟随当前阅读章节。实际能显示的评论以网站返回为准。

旧下载 HTML 按需迁移时，没有有效图片地址的 `img` 保留为图片不可用提示；没有 HTML 的旧组件列表采用同样处理。已存在的 v2 空地址图片在阅读时显示该提示，不改写正文快照或指纹。正文图片在加载期间显示占位标签，超时或加载失败后保留不可用标签；标签旁的纯文字“重试”按钮仅重新加载对应图片，滚动与分页阅读共用此行为。下载时缺图不再使已保存正文的章节任务失败，原图片地址与正文指纹保持不变，后续继续下载仍可补齐缺图。

前后导航表示论坛帖子顺序，不等于目录章节序号。

### 6.3 wenku8 站外章节

ESJ 目录中形如 `https://www.wenku8.net/novel/{bookGroup}/{bookId}/{chapterId}.htm` 的 HTTPS 链接由原生阅读器处理。来源识别检查解析后的完整主机和路径；其余站外链接默认在应用内 WebView 打开，右上角可交给系统浏览器。wenku8 响应从有大小限制的原始字节解码，按 HTTP charset、HTML meta charset、HTML http-equiv charset、GBK 的顺序选择编码。

正文只读取 `#content`，标题优先读取 `#title`。清除脚本、样式、广告、导航及书签控件后，正文仍经共享的 `analyseComponents` 解析；图片相对地址以章节 URL 解析为 HTTPS wenku8 地址。缺少正文容器或正文过短时拒绝缓存。详情页的目录顺序优先于站外页面自己的上一页、下一页链接，因此跨来源翻章仍由 ESJ 目录决定。

Cloudflare 挑战在正文解析和缓存之前识别。冷会话先尝试 OkHttp；遇盾时前台使用受限的隐藏 WebView/Chromium 直接取得章节 HTML，不依赖搬运 clearance 后由 OkHttp 重试。热浏览器会话优先在同源页面内使用带 Cookie 的 fetch，失败时退回章节顶层导航；浏览器已确认需要人工验证时不再重复请求。成功后尽力将浏览器 Cookie 同步到独立的 wenku8 CookieJar，供 OkHttp 图片请求与下次冷会话尝试使用；Cloudflare 仍可能因传输指纹不同拒绝 OkHttp。浏览器会话退出阅读器后销毁，空闲 60 秒也会回收。只有后台浏览器无法取得有效正文时才要求用户打开可见验证页。下载入队前，详情页以最多 2 个并发请求读取并缓存选中的 wenku8 正文；需要人工验证时，验证页可将当前正文写入缓存，再继续预取。浏览器会话仍串行处理验证与页面抓取。后台下载不启动 WebView，遇盾保留已下载文件并通知用户返回小说详情。

挑战判定优先使用 `cf-mitigated: challenge` 响应头及实际挑战页标题、控件和安全提示标题。Cloudflare 的 `/cdn-cgi/challenge-platform/` 脚本也可能出现在含有效 `#content` 的正常章节页中，不能仅凭该脚本把章节判成挑战页。可见 WebView 在检测到新 `cf_clearance` 后继续等待章节正文最多 20 秒；检查 60 秒仍无结果时会提示用户重试，若刚检测到 clearance 则允许等满正文等待时间。WebView 加载到同一路径的有效章节正文时，只捕获标题、正文和章节导航，分 32 KiB 小块传回应用，并先经过原有解析与清理再写入本地页面缓存；UTF-8 正文超过 4 MiB 时记录不含页面数据的诊断并回退网络请求。

### 正文解析与本地存储

获取网页时仍按上述已验证 DOM 解析 `Component`，随后通过共享转换生成结构化正文。正式下载的章节文件版本为 2，正文按段落、片段、样式、注音、图片和换行保存；阅读器直接读取这些块。旧下载的 HTML 在首次读取时转换，之后阅读及搜索不再解析正文 HTML。原正文片段继续保存，供 EPUB 保留链接、表格等富格式使用。

ESJ 与 wenku8 的成功解析结果另写结构化临时缓存，复用原页面缓存的账号作用域、来源时间、TTL、容量及清理规则；刷新原网页会使派生结构失效。密码页、挑战页仍在获取或旧数据迁移边界拒绝。新增存储未改变 CSS selector、登录、评论与网站接口。

缓存采用成功提交后替换：先完成页面校验及章节解析，再通过临时文件替换正式文件，成功后才使旧结构化缓存失效；提交失败保留旧网页和解析结果。请求携带进程代际及页面请求版本，清理、失效或更新后拒绝旧请求回填。旧缓存键迁移继承原获取时间，确认新键保存成功后删除旧键。

详情页取消收藏后，若本书存在详情、章节缓存或下载文件，会显示不带背景遮罩的底部悬浮清理提示。只有点击“清理”才删除本书的页面、结构化章节和详情内存缓存，以及本书的下载目录；下载删除沿用任务取消与旧写入拦截。章节 URL 来自当前目录及下载清单，兼容 ESJ 账号作用域与 wenku8 缓存键，不清空其他书籍缓存、阅读记录或书签。关闭提示仅取消清理，不撤销取消收藏操作。

清理提示悬浮在详情滚动区域底部、评论输入栏上方；评论栏及其系统导航栏／键盘避让空间不被提示覆盖。

小说详情的内存解析缓存写入前核对来源网页版本及解析缓存清理代际；网页已更新、删除或解析缓存已清理时，旧解析结果不能回填。首页与云端历史快照计入设置中的页面缓存大小与文件数，手动清理页面时同时删除其内存和磁盘副本，并拒绝清理前已启动任务的快照写入。快照沿用独立存储，与页面 HTML、章节结构、分页批次及封面图片共用可配置缓存总配额（默认 100 MiB）；清理不删除正式下载、本地阅读历史和书签。任一缓存删除失败会反馈清理失败，同时继续清理其他缓存。

开发者可在“设置 → 诊断与系统维护 → 缓存记录”调整缓存总上限（1–2048 MiB，默认 100 MiB），统一覆盖页面、封面与图片、首页快照和云端历史快照，成功持久化后立即生效，降低上限会触发淘汰。独立缓存分析日志自动保存按上限分组的命中、未命中、强制刷新、更新、容量淘汰、占用及观测时长汇总，长期保留累计值、限制近期分段与文件大小，并可单独导出；不与系统日志混存。可选实时明细仅保留进程内最近 500 条，清空明细不影响持久分析日志。统计口径、保留策略和格式见 [缓存容量实验与分析日志](../docs/cache-analysis.md)。

正文解析错误（包括需要章节密码和空正文）向调用方报告，不使用过期网页掩盖错误；网络传输失败仍可回退到已验证的旧正文。请求令牌由进行中的请求及会话持有，版本索引随缓存文件删除或容量淘汰回收；同一键重新创建时使用新的请求及内容版本，旧令牌和来源引用不能重新生效。

搜索、小说列表和收藏分页以账户及查询参数分组，整组 HTML、分页获取时间及批次标识保存为一个 gzip JSON 快照，放在同一页面缓存目录内，计入可配置缓存总容量（默认 100 MiB），沿用页面文件统计及手动清理。第一页成功获取、解析并提交后替换整组旧分页；加载更多只加入当前批次。刷新失败保留旧批次作为 fallback，页面保留原列表并提供重试。加载更多更新失败时保留磁盘缓存及已显示列表，向调用方报告失败，不推进页码，重试仍请求同一页。搜索分页返回界面后再次核对批次，失效时重新加载第一页。不同批次的分页不能混用；推荐池发现旧请求器失效时重新打开第一页。列表更新等待网络结果或失败回退，避免后台更新磁盘后界面仍持有旧第一页。TTL 只判断是否需要更新，不按时间删除文件。

同批次的活跃会话共享已解码快照，仅在来源版本变化时重新读取磁盘；会话结束后索引不继续持有该批次。第一页和后续分页命中内存快照时，按页面缓存原有的五分钟节流更新磁盘访问时间，容量淘汰据此保留近期使用的批次，不修改页面获取时间或延长 TTL。快照直接序列化到 gzip 临时文件，避免生成整批 JSON 字符串副本。新分页须提交成功后才更新共享快照及总页数，页数减少时移除超出范围的缓存；提交失败保持原页和页数，重试仍抓取同一页。第一页或后续页的新鲜缓存无法通过页面校验或解析时重新请求网络，重新获取或提交失败时保持旧批次并报告失败；取消与批次失效异常仍直接报告。

云端书架全量同步先获取并解析全部分页，再一次提交完整缓存批次；中途失败保留旧缓存及本地书架，不能使用 fallback 冒充本次同步成功。旧版独立分页通过已知 URL 逐步纳管，新批次提交后回收能明确关联的旧分页，无法归组的历史文件继续遵循容量策略。

章节正文、图片及下载清单成功提交并发布读取索引后，回收本次保存的来源网页与结构化缓存；来源版本已经更新时保留新缓存。部分下载只回收已完整提交的章节，失败、预取阶段及未完成图片继续保留缓存。阅读器自动保存同样核对实际保存的正文后回收，正式下载中的正文 HTML 继续用于 EPUB 富格式导出。wenku8 前台预取缓存保留到后台下载真正提交成功。

## 7. 评论解析

主选择器：

~~~css
.comments-section
.comments-section.comments-page-N
.comment
.comment-header
.comment-title
.comment-author-ava .lazyload-author-ava
.comment-header img / .comment-title img / [data-avatar]
.comment-floor
.comment-meta
.comment-body > blockquote
.comment-text
.comment-footer
.forum_report
.forum_reply
~~~

字段：

- 评论 ID：.comment 的 id，样本形如 comment-{commentId}。
- 用户名：优先读取 `.comment-header .comment-title` 的文本（包含带个人主页链接和无链接的纯文本用户名），缺失时读取原有用户链接文本。仅用户名为空时由界面显示“匿名用户”；无链接不代表无用户名。
- 用户 URL：通常 /my/profile?uid={uid} 或 /my/profile.html?uid={uid}。
- 用户头像：优先读取 .comment-author-ava .lazyload-author-ava 的 data-src、data-original 等懒加载属性；懒加载完成后再读取 style 中的 background-image，兼容旧模板的 img/[data-avatar]。
- 楼层：.comment-floor。
- 日期：排除 .comment-floor 后的 .comment-meta，或 time[datetime]/[data-time]；不能把 #楼层当作日期。
- 内容：.comment-text 的 HTML 或纯文本。
- 回复引用：评论正文前的 `.comment-body > blockquote`；引用与当前回复正文分开保存和显示。
- 操作：.forum_report、.forum_reply。

评论区统一由客户端按解析后的评论顺序每页 15 条分页，忽略站点不一致的 .comments-page-N DOM 分组；分页链接通常是 javascript:void(0);，不要把它当作服务端 URL。

### 8.1 会员侧栏

### 8.2 收藏列表

页面：/my/favorite。

选择器：

~~~css
#fav_sorting
table.table
table.table tr
table.table a[href^="/detail/"]
table.table a[href*="/forum/"]
~~~

每行一个 td，通常包含详情链接、最新章节链接、最後觀看 和 更新日期。默认页每页 20 行；排序选择会先进入 /my/favorite/new/ 或 /my/favorite/udate/，后续分页分别跟随页面生成的裸数字或 /udate/ 数字链接。由于裸数字页依赖首个路由建立站点会话排序，客户端进入排序时会强制刷新首个路由，同时保留旧缓存作为网络失败回退。

### 8.3 观看记录

页面：/my/view。

客户端直接按照 `/my/view` 页面的 `table.table` 行顺序解析并展示，不进行反转。该顺序契约由 `history.html` parser fixture 固定测试。

云端历史卡片在后台匹配章节目录索引；计算中和未匹配到章节时显示中性占位及无进度的轨道，匹配成功后才显示章节位置和全书进度，不将未知位置显示为 100%。

2026-10-03 核对维护者提供的 `觀看記錄 - ESJ Zone.mht`：存档包含 29 个 `tr[id^='view_']`，View ID 并非单调排列；每行只有书名、最后观看章节和删除按钮，没有观看时间或排序字段。存档未保留 JavaScript，相关 CSS 未改变行顺序。因此只能确认保存后的 DOM 顺序，不能从该文件证明服务端按最后观看时间排序，也不能按 View ID、小说 ID 或章节 ID 重排。

该存档的详情和章节链接是绝对地址（浏览器保存网页也可能将相对地址转为绝对地址）。详情选择器使用 `h5 a[href*='/detail/']`，同时接受绝对和相对链接，避免漏行；`.book-ep` 与 `.view-log` 是同一 `.product-info` 下的兄弟节点。脱敏回归用例覆盖这种结构、混合链接形式及非单调 View ID，确保保留完整行顺序。此解析修正不证明线上乱序根因已经解决。

选择器：

~~~css
table.table
.view-log
.view-del
.book-ep
~~~

删除按钮 `.view-del[data-id]` 的 `data-id` 是观看记录自身的 View ID，不是小说 ID 或章节 ID；优先读取该字段，缺失时可取 `<tr id="view_{vid}">` 的 `view_` 后缀。不得从 `novel-` 行 ID 推导删除目标；无 View ID 的记录仍可显示和阅读，但不能删除。客户端 `HistoryNovel.vid` 保存该 View ID，并发送给 `/inc/mem_view_del.php`。

### 8.4 资料表单

页面：/my/profile。

当前用户头像沿用 `aside img, .profile-avatar, [data-profile-avatar], img[data-avatar]` 选择器，优先读取 `data-src`，再读取 `src`，避免把懒加载占位图当成头像。客户端按账户保存最后一次成功加载的头像地址，并复用共享 Coil 内存／磁盘缓存；资料刷新时先恢复该图片，新图加载成功才替换，空地址或加载失败保留已有头像。头像图片仍受应用图片缓存清理与容量策略管理。

旧资料缓存中的头像地址可能为 `/uploads/...` 等相对路径；恢复图片前先通过 `EsjzoneUrls.resolve` 解析，再生成共享 Coil 缓存键。仅在缓存图片恢复成功后保存解析后的成功地址。

主要字段：

- input[name=nickname]
- input[name=pwd]
- input[name=pwd2]
- select[name=age]
- select[name=open_msg]
- select[name=display_post]
- input[name=blacklist]
- input[name=rmlist]
- input[name=content]

资料简介由 Froala 在 contenteditable=true 元素中编辑，提交前同步到 hidden content。编辑表单 .form-edit 的 method 为 POST，未提交验证。

## 9. 论坛与 FAQ

### 9.1 论坛分类与首页分组

论坛首页 `/forum/` 包含两组论坛版块，在解析与界面中划分为两个部分（数量比为 5:3）：
- **ESJ-曉朔國度**（5 个版块）：对应 ID `1584680829`、`1584678947`、`1584622251`、`1584622325`、`1584679807`。
- **天空大公國**（3 个版块）：对应 ID `1584622376`、`1584622613`、`1584622628`。

分类链接通过 `table.forum-category` 或 `table` 中的 `/forum/{categoryId}/` 匹配，所属分组优先根据表头文本（如 `thead`, `caption`, 标题元素）或已知 ID 集合映射；未分配时按 5:3 比例降级回退。

页面 `/forum/{categoryId}/` 使用 `.table.forum-board-detail` 的四列卡片矩阵。每个 `td` 内第一个匹配 `/forum/{categoryId}/{boardId}/` 的 `a[href]` 是一个子板块入口，`.forum-desc` 包含主题数、回复数和最后发表日期；解析器必须遍历全部 `td`，不能按 `tr` 只取一个入口。

子板块页 `/forum/{categoryId}/{boardId}/` 有两种语义：

- ESJ 小说旧入口：五个 ESJ 分类中的两段式页面存在匹配 `/detail/{novelId}.html` 的小说标题链接，例如 `/forum/1584622325/1788015863/`。客户端只解析该详情链接并直接进入小说详情，不解析或展示旧页面的主题表。
- 普通讨论板：页面没有作品详情链接，例如 `/forum/1584622376/1585405336/`；主题链接中的第一个 ID 是实际板块 ID，而不是父分类 ID。

主题表使用 `#dataTable[data-url]`。初始 HTML 的 `no-records-found` 行可能只是 Bootstrap Table 尚未完成动态加载的占位符；当 `data-url` 的 `totalRows` 大于 0 时必须请求其 JSON 数据并解析 `rows`，不能把初始占位符当作空列表。`totalRows=0` 才可以直接返回空列表。无法识别 JSON、行结构或主题链接时应返回加载错误，不能静默转换为空页。

### 9.2 FAQ

页面 /faq/ 的问答目录链接为 a[href^="#q"]，说明图片链接为 /assets/img/faq/...。当前 DOM 文本能看到四个问题标题，但折叠内容显示不完整，具体答案 HTML 不作为模型字段依赖。

## 10. 资源和清洗

- .lazyload[data-src]：优先保存 data-src，不要把空 src 当作没有封面。
- 正文图片是普通 img，可直接收集 src。
- 外部脚本、广告、统计和 Cloudflare beacon 不属于业务正文。
- 公共页有多处 createBook 模态表单，解析当前页面功能时应按表单 ID/业务容器过滤。
- 详情页控制台观察到一条 .comments-page-1 #https://www.esjzone.cc/detail/1716174812.html 选择器语法错误，属于站点前端已知问题线索，解析器不应依赖其滚动逻辑。
