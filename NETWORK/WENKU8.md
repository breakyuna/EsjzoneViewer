### 原生输入与受控 WebView 登录（2026-10-10）

先前匿名请求登录页返回 403，未取得 DOM。用户随后提供登录页 MHT：
`轻小说文库 - 最新最全的日本动漫轻小说在线阅读与下载基地.mht`。
本轮只读取并提取结构，没有复制该文件到仓库，没有读取或输出账号、密码、Cookie。
MHT 的主文档地址为 `https://www.wenku8.net/login.php`，原文声明 GBK；
MIME charset 与原字节不一致时，离线检查采用 GB18030 解码。WebView 继续使用真实站点文档编码。

已由该文件确认：

| 项目 | 实际结构 |
| --- | --- |
| 表单 | `form[name="frmlogin"]`，`method="post"` |
| 账号 | `input[type="text"][name="username"]`，`maxlength="30"` |
| 密码 | `input[type="password"][name="password"]`，`maxlength="30"` |
| 有效期 | `select[name="usecookie"]` |
| 提交按钮 | `input[type="submit"][name="submit"]`，value 为包含不换行空格的“登 录” |
| action | `https://www.wenku8.net/login.php?do=submit&jumpurl=http%3A%2F%2Fwww.wenku8.net%2Findex.php` |
| 编码／隐藏字段 | 无显式 enctype、accept-charset，使用默认 URL 编码；该快照未发现隐藏字段 |

有效期四项为浏览器进程 `0`、保存一天 `86400`、保存一月 `2592000`、保存一年
`315360000`。原生页面首次默认最后一项，通过现有 SettingsDataStore 的
`wenku_login_duration` 记忆选择；非法值恢复默认。用户选择立即用于本次提交，
不会因 DataStore 异步写入延迟而提交旧选项。修改偏好不会改变已有会话的策略。
不将 `315360000` 改为 `31536000`，不据此承诺会话持续一年或十年。
账号和密码只使用非 saveable 的 Compose 内存状态，旋转时不恢复；提交调用后即清空原生密码，
网页原生约束校验失败时立即清空网页密码；成功／退出时清空当前网页密码并移除临时提交标记，不为清理字段重新加载登录页。

流程为原生输入 + 同一个受控 WebView：

1. 从 MainActivity 提供的 `LocalActivity` 获取有效 Activity 并创建 UI WebView；
   `LocalContext` 是 `createConfigurationContext` 生成的语言资源 Context，不能沿其包装链查找 Activity。
   等待现有独立 CookieJar 恢复 Cookie，先加载受保护首页。
   已登录文档进入会话核对，匿名重定向进入真实登录表单，不要求已有有效会话重新登录。
2. 原生面板覆盖仍正常布局的 WebView，不使用 GONE、零尺寸或暂停加载；隐藏网页不参与无障碍焦点。
   已有表单、人工验证和登录尝试期间，“打开网页登录”展示当前 WebView。
   准备失败且尚未发起登录尝试时，用户点击该入口会在同一 WebView 重新导航到登录页并展示网页；
   返回原生面板不创建新实例或重置文档。
3. 仅在当前 WebView 地址与文档均属于允许的 HTTPS 文库来源，并且表单、POST action、默认编码、
   四个选项和真实提交按钮均检查通过后，启用原生提交。点击后以 Gson JSON 序列化参数，
   evaluateJavascript 填写字段、触发 input/change、点击实际提交按钮；保留 action、按钮值、隐藏字段
   和浏览器编码／校验流程，不构造 HTTP 登录接口，不添加 JavascriptInterface。
4. 原 action 中的 jumpurl 不改写；若主文档跳转到已确认的本站 `http://www.wenku8.net/index.php`，
   仅将该精确首页地址升级为 HTTPS。其他非允许来源仍拒绝；URL 跳转本身不证明登录成功。
5. 提交期间禁用重复登录。回调仅读取有限状态和数字有效期；sessionStorage 中仅保存随机尝试标记
   与有效期值，用于辨认用户在完整网页中提交的实际选项，不保存账号密码。
   页面加载、旋转或验证完成不会自动填写或重新提交。人工验证只交给用户操作。
6. 活跃页面对准备／验证状态做有界 DOM 检查，超时保留未知状态；用户可手动核对会话或重新打开登录页。
   “重新打开登录页”是用户明确重试动作；准备失败后点击“打开网页登录”也会重试导航。
   正常切换原生／网页和成功清理不重新导航。

结果判断：

- 表单检查完成前为准备中；触发真实按钮后为提交中。JS 回调成功和 onPageFinished 均不是认证成功。
- 既有已观察的欢迎区文本与同源退出入口共同作为浏览器登录信号；随后先同步 Cookie，
  通过现有文库客户端强制请求首页、禁止隐藏浏览器自动求解，验证业务 DOM 和同样的身份信号，
  两者均成立才显示已登录与返回文库。回到原页面沿用既有强制刷新逻辑。
- 页面准备／提交阶段每次导航的等待窗口为 40 秒；身份信号识别后，原生网络核对另限时 35 秒。失败、挑战、解析变化或超时显示状态未知，不报密码错误、不清除原有会话。
- 已有 Cloudflare 文档标记触发人工验证页面；仍是登录表单时允许用户继续操作。
- 本次没有拒绝页样本。提交后仅对“用户名或密码（输入）错误”“密码不正确”“登录失败”等明确
  拒绝词作保守识别，不假设错误容器 selector；未匹配的响应保留未知状态并展示网站原文。
  这些候选词及成功区的完整实站 DOM 仍需真实登录／错误密码设备验收。

Cookie 与生命周期：

- 复用 CookieManager、加密 `wenku8_cookies`、独立 CookieJar、会话代际和清理机制。
  不重建 Cookie expiry，不向 ESJ、图片 CDN 或其他来源发送文库 Cookie。
- 同源主文档加载完成即保存浏览器 Cookie 快照，包括尚未识别出登录成功的页面；原生核对进行中及成功后不重复回灌，避免覆盖原生请求刚轮换的 Cookie。快照保存不代表身份核对成功。
- 只有观察到新登录成功信号后，才根据该次实际提交选项在 IO 线程同步记录进程策略；写入与会话清除互斥并核对捕获的会话代际，迟到写入不恢复已清除的策略。单改原生偏好不会追溯延长
  或缩短旧会话。“浏览器进程”会话下次应用进程初始化时，使用既有文库作用域清理删除
  原生 Cookie、加密快照及已知浏览器 Cookie；UI 和隐藏传输的 Cookie 恢复等待清理完成。
  其他选项继续使用原有加密快照恢复，不改变 ESJ。快照缺少真实到期属性，服务端仍可随时使会话失效。
- 清除本地会话不等于网站服务端退出，不调用未确认的登出接口，也不调用 removeAllCookies。
- UI WebView 只由 Navigation 3 entry 的 ViewModel 持有。通过 DisposableEffect 创建并绑定 Activity，组合计算不创建或导航 WebView；卸载解除绑定，
  旋转保留文档并允许安全服务器跳转；重挂载只检查状态，不重放提交。旧脚本回调受页面与挂载代际约束，
  退出取消检查和业务请求，停止加载、清理临时密码，销毁 WebView，不在进程级对象中保留 Activity。

原生输入功能首次实现时仅完成静态契约检查、`git diff --check`、三套语言 XML／资源名称一致性、
脚本 Node `--check` 语法检查与新增源码敏感信息检查；当时未运行 Gradle、JVM 测试、Lint、APK 或设备测试。
后续审查修复及其验证记录见本文件末尾，静态验证不证明设备登录与浏览器 Cookie 行为。
待设备验收：窄屏／分屏／横屏及软键盘、正确账号／错误密码／特殊字符密码、人工验证继续操作、
提交中旋转／退出、已有会话直接进入、长期选项登录后杀进程重启、浏览器进程结束行为，
以及清理后旧请求／旧回调不能恢复会话。

### 会话过期提示与登录入口（2026-10-10）

用户反馈选择“保持本次浏览器活动”后，重启访问失败，重新登录恢复。此反馈说明该次故障可通过重新登录恢复，不将所有安全验证异常等同于 Cookie 过期。

保留现有异常区分：同源登录页跳转或业务解析识别到登录表单时，提示“未登录或文库登录已过期”；仅有安全验证异常时，提示“文库会话可能已过期或需要站点验证”。首页、列表、搜索和详情的安全验证错误也提供登录按钮，打开用户操作的会话 WebView，返回后沿用既有强制刷新；同时保留站点验证入口。不自动弹出登录、不清除会话，不根据重启或 Cookie 是否存在推断服务端登录状态。

### 隐藏浏览器空文档与 fetch 诊断修正（2026-10-10）

设备截图显示原生首页返回 `403, challenge=true`，随后隐藏 WebView 约 0.74 秒即返回
`htmlChars=39`，请求与最终 URL 均为首页。39 与空 HTML 骨架长度一致，但截图没有网页正文，
不能据此断言实际内容。源码确认旧流程仅凭 WebView URL 与 readyState 便抓取，未等待本次导航完成。

导航现在等待本次 onPageStarted／onPageFinished，并检查当前 DOM 的 location.href 与浏览器
地址一致、readyState 为 complete，再抓取；空正文骨架或仅脚本／样式的空正文继续等待，
不按 HTML 长度判断，不吞掉正常短错误页或图片正文。依据
[Android WebViewClient 回调说明](https://developer.android.com/reference/android/webkit/WebViewClient#onPageFinished(android.webkit.WebView,%20java.lang.String))，
onPageFinished 仅作为主文档加载完成信号；不宣称视觉帧已经绘制。
页面或章节的浏览器结果在业务解析失败后撤销 ready，不清除 Cookie；导航开始也撤销 ready。
fetch 失败只记录固定阶段 request／http／origin／read／decode 与数字状态码，不输出原始
脚本错误消息；request 阶段仍不能细分网络、CORS 和 redirect:error 拒绝。

补充空文档、短错误页和图片正文的 JVM 回归用例，尚未执行。静态契约与 diff 检查通过，
并用 Node 对实际 fetch 脚本模拟成功、HTTP 错误、来源不符、请求拒绝、读取失败、解码失败
共六个分支，全部通过；模拟不涉及实站或 WebView。JVM／Lint／APK／设备验证尚未执行，
不能据此宣布实站访问恢复。

### 隐藏浏览器最终地址修正（2026-10-10）

收到首页 `stage=browser-final-url, kind=HOME, actual=invalid-url` 报告：该错误位于
HTML 抓取后的最终地址校验，旧日志不能区分空地址、JavaScript null／undefined 或其他非法值，
不能据此推断 Cookie 失效或站点跳转目标。

导航加载现使用 WebView 自身的实际地址，并在抓取前后地址一致时返回 HTML 与地址；
页面内 fetch 则使用该次 Response.url，每次 fetch 开始时清空旧值。
两条路径分别携带结果，取消统一读取 `window.__esjWenkuFinalUrl||location.href`，
最终仍执行原有页面类型、主机和路径校验，不用请求地址代替缺失的实际地址。
诊断补充空地址、JavaScript null／undefined 和 about:blank 分类，其余非法值仍不输出原文。
此修正尚未经过设备 WebView 或实站验收，原始非法值的具体来源仍待设备日志确认。

### 原生登录空白文档处理（2026-10-10）

用户反馈原生页面无法获取表单，打开网页登录后也是空白，并提供
`Browser session closed` 堆栈。源码确认该异常属于独立隐藏传输：登录 WebView
同步 Cookie 时会递增会话代际并关闭隐藏 WebView，使旧业务请求退出；不能仅凭
该堆栈认定受控登录 WebView 被关闭，或认定表单 selector 错误。

用户补充复现：未安装本次修改时，获取表单失败后点击“打开网页登录”为空白，
点击“重新打开登录页面”则正常加载。源码确认前者原来仅切换可见状态并检查旧文档，
后者会导航到 `/login.php`；此反馈证明该次失败可以通过新导航恢复，未证明首次失败的原因。
启动仍先恢复 Cookie 并检查已有会话。准备失败（结构不兼容、网络错误或状态未知）、
没有可用表单且尚未开始登录尝试时，点击“打开网页登录”复用显式重试逻辑，
在同一个 WebView 导航到已确认的 `/login.php` 并显示网页。准备中、已有表单、人工验证、
会话核对及已观察到的提交结果均保留当前文档，不因切换重新导航或提交。
检查到初始 about:blank 或空正文时继续在原有等待窗口内轮询，不立即判为表单不兼容；
超时仍保留未知状态，不自动重载或提交。返回原生面板时重新检查当前文档。
表单的来源、action、编码、控件与有效期校验保持原有限制。

`Wenku8LoginModel` 日志记录请求／实际地址、开始／完成／加载错误／HTTP 状态／超时，
以及固定的表单检查状态和结构拒绝原因；不记录原始 JS 返回值、页面正文或表单字段值。
Cookie 桥接导致旧请求失效时单独记录固定原因，便于区分后台请求取消与登录页面加载失败。
新增 Chromium 用例源码覆盖正常表单、空正文等待与额外交互字段拒绝；本轮仅做静态验证，
另补充恢复决策的 JVM 用例源码，覆盖失败后重试与正常表单／验证／提交结果保留。
未运行测试、编译、Lint、APK 构建或设备验收，首次加载失败的实际原因仍待新日志确认。

## URL、身份与导航

- 仅接入准确的 `www.wenku8.net` HTTPS 主机、443 端口、无用户信息的地址；没有启用 `.cc`／`.com` 或外部 CDN。
- 独立文库作品本地身份为 `wenku8:{bookId}`，作品 URL 为 `/book/{bookId}.htm`，目录模板为 `/novel/{bookId / 1000}/{bookId}/index.htm`；网络 URL builder 使用纯数字 bookId。
- ESJ 数字身份保持现有规则。ESJ 目录内的 Wenku 外链仍采用显式传入的 ESJ 所属作品身份与完整目录。
- Reader token 只对作品身份百分号编码；拆分第一个分隔冒号后解码作品身份，章节完整 URL 不切分。页面 key 与 registry 共用生成函数；恢复按作品身份生成来源正确的详情 URL。
- 阅读器、书签、历史封面、下载封面的 URL 回退使用来源 helper。书签逻辑身份保留冒号，文件名独立转义；统计与书架身份提取区分同数字的跨源作品。

## 传输、编码、缓存与会话

复用 `network/external/` 的独立 Wenku CookieJar、OkHttp 与隐藏 WebView，没有再建 Cookie 或网络框架。

- 业务页按搜索／详情／目录／正文分别允许路径；原生重定向最多四次，逐跳验证同源业务 URL，搜索可跳详情。浏览器 fetch 不自动跟随重定向，导航同样受来源限制。
- 非章节页复用已有 PageCache，以 Wenku 会话代际、页面类别和保留原始查询编码的 URL 区分缓存；不经过通用 UTF-8 查询解码，避免 GB2312 中文关键词合并；详情／目录按候选结构验证，搜索只有可识别书卡或单本命中才缓存。限流、挑战、缺失 DOM、版权受限页不写业务缓存。
- 统一详情入口在 ESJ 缓存及请求之前分流，不传递 ESJ Authorization。后台 Worker 不恢复文库所不需要的 ESJ 会话，也不启动 WebView；可读取前台有效页面缓存后继续既有章节下载。
- 原始字节的 GBK／GB2312 声明与缺省编码使用 GB18030；明确 UTF-8 保持优先。浏览器 fetch 使用相同兼容策略；浏览器 DOM 字符串不再次转码。该策略来自固定上游，当前站点四字节样本仍待验证。
- 正文继续复用 `analyseComponents`；正文页的辅助前后链接只允许同一文库作品，正典翻章仍以传入目录为准。
- 正常 Set-Cookie 保留其属性并使用加密存储，同时按捕获的会话代际同步至 CookieManager；旧桥接值不覆盖新的原生 Cookie。浏览器 getCookie 缺失 domain／path／expiry 属性，导入 pair 保留已观察的 URL 作用范围：根 URL 快照限本站同源，非根快照只用于采集时的完整 URL，不伪造统一有效期。快照同步提交至现有 `wenku8_cookies` 加密存储，重建 CookieJar 后原生请求直接恢复；原生 Cookie 的刷新、删除和已知到期同时更新快照，清理会话同步删除快照。
- 会话页每次同源页面加载完成和退出时调用 flush 并保存快照；原生核对进行中不重复桥接，核对成功后加载完成／退出不回灌旧浏览器快照；打开会话页和隐藏传输 WebView 前，等待已保存 Cookie 恢复至 CookieManager，不覆盖浏览器中已有的同名值。恢复仍受会话代际约束。长期选项会话可从加密快照跨进程恢复；本轮记录为浏览器进程的登录在新进程恢复前清理。服务端失效／撤销登录仍需用户重新登录；未观察到真实到期属性的桥接值不承诺永久有效。
- 手动会话导入／清理切换缓存代际；业务请求携带捕获的代际，迟到 Set-Cookie 不回写新会话。缓存写入使用请求或浏览器桥接时捕获的命名空间，并与手动导入／清理互斥。首次采集新路径不会单独切换代际，以保留详情／目录缓存供后台下载读取。清理覆盖已知 Cookie 作用域、根路径，以及已采集 URL 可能匹配的路径前缀和本站域；未采集路径仍不可枚举。未调用全局 removeAllCookies。
- 文库会话入口采用原生输入辅助真实 WebView 表单提交，完整流程及状态证据见本文件“原生输入与受控 WebView 登录”。不自动处理 CAPTCHA；只有浏览器身份信号与受保护业务核对均通过才确认已登录。清理按钮等待已知 Cookie 删除回调与 flush 后重新打开页面；只清理本地会话，不调用未确认的远端登出。
- 搜索／详情验证取得 `cf_clearance` 后由既有策略返回，不要求重定向后的页面仍匹配原始路径或章节 DOM；章节验证继续优先采用可读正文，只有 clearance 时等待正文 20 秒再回退。
- 会话页 WebView 由 Navigation 3 entry 的 ViewModel 持有，首次创建绑定有效 Activity，旋转重建复用当前文档并重新绑定 Activity，卸载解除绑定；退出 entry 时停止检查并销毁 WebView。原生账号密码不写入 SavedState 或磁盘，旋转不恢复密码、不重放提交；清理状态随 ViewModel 保留。
- 浏览器 Cookie 清理与持久化、HttpOnly／非根路径 Cookie 的完整同步及换号仍需设备验证；不能将候选代码视为真实会话验收。
