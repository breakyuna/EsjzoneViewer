# 维护注意事项

以下记录原静态审计中仍值得复查的观察项；仅说明源码路径，不代表已在设备上复现或确认当前仍是缺陷。

- `StartupCoordinator.retry()` 直接写入 Starting，失败后快速重复重试的状态转换可在修改启动流程时重新检查。
- `SettingsStateBoundary` 的 `boundRepository` 在锁外快速读取、锁内再次检查；如改变绑定线程或 repository 生命周期，应重新审视可见性。
- 旧 Room 的 `theme` 键会在迁移后删除；若需要支持很旧版本的主题偏好升级，应先核对旧版本的值和迁移语义。
- 阅读设置使用进程级协程进行 250ms 防抖保存；在防抖期间进程被终止时，最后一次调整可能未落盘。

存储性能优化保留以下一致性原则：

- 书架和历史优先发布可用的本地数据；后台进度校正不得覆盖较新的阅读位置。
- 下载只预检此次目标章节；删除、存储迁移和备份恢复应维持代际检查及互斥关系，阻止旧任务重新发布数据。
- 页面缓存的锁外读写必须在发布前校验请求令牌、代际和来源版本；缓存淘汰不得删除正式下载。
- 隐藏成人内容时，云端历史中分类未知的作品应等待验证，不能把未知当作已确认的非成人内容。
