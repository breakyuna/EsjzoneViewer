# 缓存容量实验与分析日志

Debug 版入口：设置 → 诊断与系统维护 → 缓存记录。

Release 版隐藏此入口，关闭实时明细及自动分析汇总，不读取或写入分析日志，也不启动周期保存任务。缓存总上限固定为 100 MiB（104857600 字节），忽略此前保存的自定义上限；已有分析日志保留，恢复旧的缓存记录页面时转到设置页。以下容量调整与分析日志说明适用于 Debug 版。

缓存总上限可输入 1–2048 MiB，默认 100 MiB。成功写入 DataStore 后立即生效，重启时恢复；升级沿用原页面缓存上限。此配额与存储分析中的“缓存”分类一致：页面缓存（压缩网页、章节结构和分页批次）、封面与图片缓存、首页快照、云端历史快照共用一个磁盘容量上限。正式下载、书架持久封面、字体、备份、数据库和分析日志不占用此配额；运行时内存缓存仍按各自内存策略管理。

降低上限后立即执行一次全局容量淘汰，日常写入后合并调度后台淘汰，按各层最近使用时间优先回收旧条目。页面访问时间沿用五分钟更新间隔；首页和历史的内存命中、图片内存与磁盘命中也刷新对应磁盘条目的最近使用时间。图片的读取、提交和删除通过 Coil 的公开 DiskCache 接口完成，正在读取或写入的图片在关闭后重新检查容量，不直接删除 Coil 文件。

图片缓存新增只保存摘要键和最近使用时间的回收索引。首次升级时旧图片缓存会失效重建一次，避免保留无法按键安全删除的旧条目；正式下载和持久书架封面不受影响。

“设置 → 本地存储与缓存管理”的存储占用分析保留六个主分类，点击分类行展开明细，再次点击收起；可同时展开多个分类，不显示额外展开按钮。展开时环图对应区域同步按明细占用分段，颜色与明细行一致；明细百分比均以全部存储总量为分母，展开与收起不改变统计总量。

| 分类 | 明细 |
| --- | --- |
| 应用安装文件 | 安装包（含拆分安装包）、其他安装文件 |
| 离线下载 | 章节内容、下载图片、下载记录与其他文件 |
| 缓存 | 页面缓存、封面与图片缓存、首页快照、云端历史快照 |
| 自动备份 | 备份归档、临时备份与其他文件 |
| 阅读资源 | 书架封面、阅读字体 |
| 应用数据 | 数据库、网页浏览数据、应用设置、缓存分析日志、其他应用数据 |

各分类及明细共用同一次后台扫描结果。应用安装文件总量由系统提供，其他安装文件为扣除 APK 文件后的剩余；其他应用数据为系统数据总量扣除已分类文件后的非负剩余。存储分析中的“缓存”与缓存总上限覆盖同样的四类磁盘数据；分析日志归入应用数据。临时写入和正在使用的图片可造成短暂超额，提交或关闭后会再次执行回收。

## 保存与导出

分析汇总自动开启，与“实时明细”开关独立。日志保存到应用私有持久目录 `files/cache_analysis/cache-analysis.json`，不使用系统日志，也不随缓存清理。右上角“导出缓存分析日志”通过系统文件选择器导出独立 JSON 文件。

- `totals`：按统计范围 `cacheScope` 和实际缓存上限分组的长期累计汇总；重启、切换上限或清空实时明细不会删除。
- `recent`：近期通常按五分钟时间桶合并的汇总，最多 2016 段；跨空闲时段的窗口可能更长。上限切换时分段，并记录 `nextLimitMiB`。更早分段被归入累计汇总，不永久保存逐次命中、条目 ID 或淘汰明细。
- 正式日志最多 8 MiB，超量时压缩近期分段数量，保留累计汇总。原子替换期间会使用一个临时文件，不建立持续增长的日志档案。
- 每 60 秒尝试保存，进入后台、修改上限、打开记录页和导出时也会保存；无新活动时跳过重复写盘。强停或崩溃可能丢失最近尚未落盘的数据。保存失败会在页面显示错误，并在内存按上限合并待保存计数后重试。

日志只含统计范围、层名、时间、容量、数量和比率，不含 URL、搜索词、账号、凭据、正文、异常文本或实时事件摘要标识。图片、首页与历史快照均纳入分析及实时明细。详情内存缓存的命中和更新也单独记录，其条目数淘汰不计入磁盘容量淘汰频率。

日志格式升级为 `schemaVersion: 2`。新数据使用 `cacheScope: ALL_DISK`；旧版日志自动标记为 `PAGE_ONLY`，保留在导出文件中，按范围分别累计，记录页只展示新的全部磁盘缓存统计。旧范围与新范围的相同上限数据不会合并。

## 指标口径

每段及累计汇总记录 `limitMiB`、起止时间、单调时钟观测时长 `durationMillis`、末次占用 `sizeBytes`、占用峰值 `peakBytes`、文件数 `entries` 和淘汰轮次 `capacityPasses`。时间戳为 Unix 毫秒，大小为字节，上限单位为 MiB。

`layers` 分为 `PAGE`（网页）、`CHAPTER`（章节结构）、`LIST`（分页批次）、`IMAGE`（封面与图片）、`HOME`（首页快照）、`HISTORY`（云端历史快照）和 `DETAIL`（详情内存）：

| 字段 | 含义 |
| --- | --- |
| `freshHits` / `misses` | 有效新鲜缓存命中 / 未命中（含过期或无效内容） |
| `forcedRefreshes` | 明确绕过缓存的请求，含手动刷新及分页网络抓取；不进入命中率分母 |
| `staleUses` | 旧缓存回退事件数 |
| `updates` / `writtenBytes` | 成功提交次数 / 提交文件字节数累计，覆盖旧文件仍计入写入量 |
| `capacityEvictions` / `evictedBytes` | 容量淘汰文件数 / 淘汰字节数 |
| `otherRemovals` | 手动清理、失效、下载回收等非容量删除次数 |
| `failures` | 缓存失败事件数，含旧写入被拒绝 |

图片以每次完成的远程图片请求为统计单位，内存或磁盘返回计为命中，需要网络获取或请求失败计为未命中；禁用磁盘读取的请求计为强制获取。首页、历史以有效快照读取为单位。

`freshHitRates` 保存各层的 `freshHits / (freshHits + misses)`，没有有效查找时不报告比率。一次读取可能先查章节结构、再查网页，所以应分层比较，不能将各层相加视为用户请求命中率；内部来源引用及缓存存在性探测不计入查找数。

`capacityEvictionsPerHour` 为容量淘汰文件数除以观测运行小时；观测时长可能包含后台停留，分析时同时参考 `capacityEvictionsPer1000Lookups`（每千次非强制查找的容量淘汰数）。页面缓存按摘要文件名淘汰，该目录的容量删除统一计入 `PAGE`，不据文件名猜测原内容类型；图片、首页及历史容量删除分别计入 `IMAGE`、`HOME` 和 `HISTORY`。图片提交按一条包含图片数据和响应元数据的缓存条目计数；首页和历史的内存更新不产生磁盘写入字节。容量淘汰与其他删除分开统计，避免把手动清理或下载成功回收误判为缓存太小。

建议每个候选上限使用相近的阅读、浏览和下载负载，比较分层命中率、容量淘汰频率、峰值占用和有效样本量。刚修改上限后的预热数据与稳定使用阶段应结合 `recent` 分段查看；这些日志用于分析实际使用，不能单独证明延迟或设备性能变化。
