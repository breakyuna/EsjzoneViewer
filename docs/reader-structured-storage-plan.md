# 阅读器结构化正文与增量下载实施计划

状态：基础改造已实现，静态检查、272 个 JVM 单元测试和 Android Lint 已通过；Android 测试代码编译通过。现状核查部分记录改造前状态（2026-10-04）。

已落地：显式 `ChapterBody` 逐章 v2 存储、共享转换、ESJ/文库结构化缓存、旧章按需迁移、并发目录合并、缺图续传、字符锚点、繁简位置映射、全书字符权重进度、逐章搜索及跳转/高亮接口、TXT/EPUB 和 v1/v2 备份适配、Room 11 非破坏性迁移。

搜索页面、网站已有正文改写同步及本地编辑不在本次交付内。设备上的定位、手势和 Android 持久化效果需另行验收；验证结果见文末。

## 1. 已确认范围

- 在线正文在获取后转换为结构化数据；已缓存、已下载正文直接从结构化数据恢复阅读。
- 正式下载按章节增量补齐：新增章节、此前未选章节、失败章节及缺失图片。
- 按用户最新要求，取消已有正文的远端修改同步、本地正文编辑，以及正文改写后的差异合并、标记重定位。
- 已成功保存的正文作为不可变内容快照；目录增加章节不重写原有正文。
- 进度、划线、搜索基础、导出、备份等必须随存储格式一起适配。这是现有功能兼容，不是正文修改同步。
- TXT/EPUB 继续作为导出格式。内部采用逐章 JSON 和独立图片文件。
- 本计划不引入定时追更任务；用户刷新目录并再次下载时补齐新增内容，阅读自动保存沿用现有开关。

搜索分两步：本次基础改造提供可搜索文本、位置映射和搜索跳转能力；独立列出章内/本书正文搜索界面的后续实施步骤。网站书名搜索不改成正文搜索。

## 3. 数据格式

### 3.1 逐章结构化快照

实现采用下载章节 v2，manifest 声明可读取的章节格式。下表为字段职责，实际命名对照见第 11 节。

| 字段 | 用途 |
| --- | --- |
| `schemaVersion` | 文件结构版本；用于旧格式识别与迁移 |
| `parserVersion` | 生成正文结构的解析规则版本；用于诊断，不自动重解析已有下载 |
| `chapterKey`、`sourceUrl` | 章节稳定身份及原始解析基址 |
| `name` | 获取正文时的章节标题；目录显示名称由当前目录提供 |
| `contentFingerprint` | 规范正文块的确定性摘要，用于确认位置和搜索结果属于同一快照 |
| `blocks` | 按原顺序保存段落、文本片段、样式、注音、图片引用及换行 |
| `textLength` | 统一规则下的正文文本长度，不包含标题、注音读音、图片 URL |
| `assets` | 图片原始 URL、相对文件名、媒体类型、保存状态 |
| `sourceHtml` | 正文片段快照，保留给富结构 EPUB 导出及旧格式兼容 |

实现约束：

1. DTO 使用显式类型字段，例如 `paragraph`、`image`，以及明确的样式编码。不得直接依赖 Gson 推断 sealed interface、Compose 对象或 Kotlin 类名。
2. 复用现有段落/片段边界；不在本次格式转换时重新分段、合并相邻段落或修改空白规则。
3. 块标识采用快照内固定序号即可；锚点以 `chapterKey + contentFingerprint + blockIndex` 限定。取消正文改写同步后，无须跨版本段落匹配或持久 UUID。
4. 指纹基于规范化的正文语义数据。图片下载位置、保存时间、目录名称和排序不参与指纹，避免补图或追更使旧位置失效。
5. 样式的存储顺序必须确定；恢复成现有 domain 对象时也要保持旧签名使用的表现，单纯集合等价不足以证明旧划线签名兼容。
6. 图片保存相对路径，运行时解析为本机 URI；备份恢复不能依赖旧安装的绝对目录。
7. `sourceHtml` 仅保存正文容器，不保存评论、认证表单或完整账户页面。新格式阅读、搜索、完整性判断不读取或解析它。

保留 `sourceHtml` 的理由来自现有实现：EPUB 的富结构清理器能保留当前 ReaderBlock 尚未表达的表格、链接等内容。首版移除它会造成导出回退；因此本次不承诺彻底删除 HTML 文件内容，而是消除日常阅读对 HTML 解析的依赖。

### 3.2 文本与位置规则

- 字符偏移使用 Kotlin/Compose 一致的 UTF-16 索引；选区边界避开代理对，用户操作按可见文字边界处理。
- 正文片段中的换行保留；段落之间使用约定的分隔符。搜索文本同时产生“文本区间 → 块序号/块内区间”的映射。
- `textLength` 及前缀长度从 blocks 得出；可持久化派生长度，但 blocks 是唯一正文依据，版本不匹配时重新计算。
- 注音搜索默认搜索正文底字，不将读音混入正文字符计数；图片和标题分别定位，不向正文插入 URL 或提示文案。
- 源文本和繁简转换后的显示文本建立区间对应关系；不得假定转换后字符串长度永远相同。底层文字、划线和搜索高亮要采用同一显示映射。

### 3.3 临时缓存与正式下载

- 两者共用编解码和正文模型，保留不同存储目录及生命周期。
- 优先级：内存结果 → 正式下载 → 未过期结构化临时缓存 → 原 HTML 缓存的一次性转换 → 网络获取。
- 过期临时缓存沿用现有刷新/网络失败回退语义，不能因为增加结构化缓存而永久冻结普通在线正文。
- 正式下载正文不自动覆盖；临时缓存因过期重新抓取的结果也不覆盖正式下载。
- 结构化临时缓存加入现有页面缓存清理、容量统计和配额，避免新增无限增长缓存。
- 读取临时缓存不等于“已下载”；自动保存开关只决定是否进入正式下载存储。

## 4. 增量更新规则

### 4.1 增量的定义

增量单位为章节和资源，不是 HTML 字节差异或段落补丁。

| 情况 | 行为 |
| --- | --- |
| 目录新增章节 | 添加目录记录；仅当本次选择包含该章时获取正文 |
| 原有未选章节被选中 | 下载该章，不重下其他章节 |
| 正文和图片完整 | 直接跳过，不解析 HTML、不重写正文文件 |
| 正文完整、部分图片缺失 | 仅补缺失图片，保持正文块和指纹不变 |
| 上次失败、文件缺失或损坏 | 重新获取对应章节，保留其他成功章节 |
| 旧格式有效章节 | 从本地一次性转换，优先避免网络重下 |
| 目录标题或顺序变化 | 更新目录元数据，以章节键继续关联原正文 |
| 目录暂时少了旧章节 | 保留本地正文，不据此自动删除或认定下架 |
| 网站修改已下载正文 | 本次不检测、不覆盖；需要新正文时仍由用户删除相应下载后重新获取 |

补图是“缺失资源补齐”，不检测同一个图片 URL 在网站上的内容替换。

### 4.2 身份与目录

- 沿用 `NovelDownloadStore.chapterKey()` 的镜像归一化和 fragment 区分规则；不得使用标题、章节编号或当前序号作为文件身份。
- 文库章节维持其来源身份；不将非 ESJ 主机错误归一为 ESJ 章节。
- 网站目录是导航排序来源；论坛 prev/next 只在缺少目录时辅助导航。
- 完整目录刷新与阅读窗口提供的部分目录必须区分。部分目录只能补充，不能覆盖已知完整目录或把 `complete` 判为 true。
- 完整目录刷新后，已确认的目录顺序优先；只存在于旧本地清单的条目继续保留，明确作为本地保留项处理，不混入当前网站目录的完整性分母。
- 下载数量、本次所选完成数量、当前已知完整目录的完成状态分别计算；选中 10 章全部完成不代表全本完成。
- `complete` 表示已知目录范围内正文及所需图片完整，不表示作者已经完结。

### 4.3 写入与并发

1. 网络及转换在后台执行；章节文件先写同目录临时文件，再原子替换。
2. 文件提交后，在现有锁/写入世代保护下重新读取最新 manifest，按章节键合并本章结果；不提交任务启动时持有的整本旧清单。
3. 显式下载、阅读自动保存、密码解锁保存、旧数据迁移都走同一个提交方法，防止新增章节相互覆盖。
4. 同章竞争时重新检查已提交有效快照：已有正文优先保留，只合并缺失资源。不同章节的完成结果可以分别提交。
5. 删除下载继续取消任务并使旧写入世代失效，避免迟到写入重新创建已删除的书。
6. 若进程在章节文件写完、manifest 更新前停止，下次扫描或对应章节访问时识别有效文件并补记，不重复下载。
7. 完整性检查改查版本、结构、正文状态及资源存在性；密码页/挑战页在进入结构化存储前拦截，不在每次读取 v2 时解析 HTML。
8. “正文已保存”与“全部资源齐全”分开记录或推导；补图失败时正文仍可读，下载任务仍报告未完整成功。

### 5.1 精确位置与百分比

- 新增可空位置字段，建议保存为一个带版本的 `anchor` JSON 字段，避免分散 nullable 字段出现不一致。位置类型区分标题、文本、图片、章末。
- 文本锚点：章节键、正文指纹、块序号、块内 UTF-16 偏移；图片锚点另保存图片内比例。
- 翻页模式使用页首对应的源文字位置；滚动模式根据 `TextLayoutResult` 的可见行计算字符位置，不继续用段落像素比例假装精确字符定位。
- 保存时排除初始化、恢复过程中的临时布局位置，沿用最近有效阅读位置规则。
- 旧历史只有比例时，按现有比例规则恢复一次；获得有效布局后写入新锚点，不声称能追溯旧记录原本没有保存的精确字符。
- 临时缓存过期重取或用户删除后重新下载，可能得到不同正文指纹。此时不做自动内容匹配；保留旧记录，续读按明确的旧比例回退，旧划线只在匹配时显示。
- 全书正文长度齐全时按已读字符数/总字符数计算；目录增长后比例降低属正常，绝对锚点不变。
- 部分章节未知时采用统一的章节进度估算，不以“已下载部分”冒充整本分母；内部以可空字符权重结果区分精确/估算状态。
- 全图章节、空正文和标题位置定义专门的块进度规则，避免零分母；全图书使用块进度，不称为字符进度。
- 长度汇总按章节加入时更新；不会每次滚动读取全部章节文件。新目录使原来“长度齐全”的汇总立即失效。

### 5.2 划线兼容

- 首轮只适配结构化读取，保留现有 `blockIndex + signature + start/end` 数据格式和繁简模式变化时的匹配规则。
- 序列化 DTO 的版本号、指纹等元数据放在外层，不把它们添加进现有 ReaderBlock 的 `toString()` 签名输入。
- 旧 HTML 转换前后的完整块、文本片段、样式顺序和渲染文本必须一致，验证签名及字符区间，而非只比较纯文本。
- 无法证实匹配的旧标记继续保存但不错误显示；不做跨正文版本自动猜测位置。

### 5.3 搜索基础与后续界面

- 本次基础：统一文本提取、段落区间映射、结果锚点、跳转后的文本高亮接口。
- 后续界面：章内搜索及本书已下载正文搜索，按目录顺序逐章在后台扫描，支持取消和分批返回；默认字面匹配。
- 第一版不要求引入全文搜索数据库；流式扫描逐章结构化文本，避免整本同时装入内存。
- 搜索结果包含章节键、指纹、块/字符范围；点击时检查正文仍在且指纹一致，不能跳到已经删除或重新下载后的错误位置。
- 如后续确有耗时问题，再增加可重建索引；新增章节只增量加入，删除下载移除对应索引，备份不保存可重建索引。
- 繁简搜索通过同一显示转换映射处理；跨段匹配须拆成多个块区间，不能将拼接文本偏移直接交给单个段落。

## 6. 迁移与兼容

### 6.1 下载与缓存

1. 新写入一律 v2；读取器明确识别 v1、v2，未知版本报告不支持，不能默认为空正文。
2. 旧章节首次阅读、搜索或导出时按需迁移；旧 HTML 有效则转换完整正文块，没有 HTML 时使用已有文本/图片列表，不伪造已丢失样式。
3. 迁移写入成功前保留旧文件；失败时本次仍可用已解析结果阅读，下次重试，不批量重下整本。
4. manifest 可在迁移期引用新旧章节，但新版 manifest 必须声明新读取协议；同书所有入口均能处理混合状态。
5. 临时 HTML 缓存按需转换，保留原 TTL 的来源时间，不能通过转换无限续期。
6. 格式升级不自动将已下载的旧正文重新按新解析规则分段；需要转换的数据必须保持可观察的正文及位置含义。

### 6.2 Room 与位置

- 改造前 `GeneralDatabase` 为 v10；现已通过 v10 → v11 非破坏性迁移，增加可空 `content_anchor` 和 `book_progress`，其他表结构保持一致。
- 保留旧 `chapterProgress` 支持历史数据和回退；更新 entity/domain 双向 adapter、备份序列化、所有新增历史记录的构造点。
- 更新导出 schema，并补实际 Room 迁移 Instrumentation 用例；不修改数据库名称。
- 章节身份不得简化为 `novelId`：文库章节和 fragment 仍通过现有书籍身份/章节键关联。

### 6.3 备份

- 新备份写版本 2；导入支持版本 1、2。仅提升下载格式而不更新顶层版本，会让旧应用误认为可完整恢复，故两个层次都明确版本。
- 按照选中类别验证和导入：只恢复历史或划线时不要求正文同时存在；以后匹配正文再恢复精确显示。
- 维持现有规则：历史保留较新记录，已有整本下载保留，不自动合并或覆盖；备份导入不额外承担增量追更功能。
- 新增/迁移后的章节文件、相对图片路径、长度元数据均进入下载备份；临时结构化缓存及搜索派生索引不进入。
- 使用现有快照锁保证备份过程中章节文件与 manifest 相符；跳过临时文件，不备份未提交中间状态。
- 自动备份继续复用 LocalBackup 协议、成功发布与轮换规则。章节密码、账户凭据排除规则不变。

## 7. 实施顺序与每阶段交付

| 阶段 | 修改内容 | 完成门槛 |
| --- | --- | --- |
| 1. 固定格式与内容转换 | DTO、编解码、指纹、共享 Component 转换、文本区间映射；准备脱敏旧文件样本 | 新旧正文结构、样式、注音、图片及旧划线签名可对照验证 |
| 2. 结构化存储和增量提交 | 逐章 v2、旧章迁移、缺图补齐、目录合并、并发提交、完整性判断 | 新增章节不重写已有正文；失败重试只处理未完成部分 |
| 3. 全部加载入口接入 | 在线结构化缓存、ESJ/文库/密码入口、预取、自动保存、repository adapters | v2 命中阅读路径不调用 HTML 正文解析；临时与正式存储清理范围正确 |
| 4. 现有功能兼容 | 下载管理、TXT/EPUB、手动/自动备份、图片操作、旧划线 | 新旧混合数据可以阅读、导出和备份恢复；富结构导出无退化 |
| 5. 精确续读与统一进度 | Room 迁移、布局位置映射、入口参数/查询、显示汇总 | 重启/换字号/切布局恢复相同源文本；新增章节不改变绝对位置 |
| 6. 搜索基础完成 | 文本扫描接口、结果锚点、可复用跳转/高亮 | 结果字符区间与实际显示匹配；新增章节即时可检索 |
| 7. 全链验证与文档 | 集中执行本地验证，整理 CI 与设备验收 | 达到下述验收门槛，明确未验证项 |
| 后续独立交付 | 章内/本书正文搜索界面及三语文案 | 用户可查找、选结果跳转；不影响网站小说搜索 |

阶段之间可做轻量静态检查；各阶段不是可单独对用户发布的完成版本。全部必要调用方适配完成后再发布，避免新格式文件被旧导出/备份代码处理。

预期新增文件只围绕正文编解码、结构化缓存、文本位置和搜索服务；不顺手迁移整个导航或重构所有 repository。

## 10. 验收边界

本计划可保证的目标是：同一有效正文快照的读取、定位、增量补齐与关联功能使用一致数据；对新增章节和缺图进行增量处理。

没有网站既有正文改写同步、跨版本标记智能重定位、本地编辑、多设备同步或定时追更。临时缓存失效、用户删除后重新下载导致正文不同的情况，只作身份校验和明确回退，不重新引入已取消的同步功能。
